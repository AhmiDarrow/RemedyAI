## Top issues (current)

### 1. bug — `GET /api/rmb/status` rewrites `config.toml` every poll

- File: `src/remedy/runtime/rmb/service.py:2563` → `sync_rmb_chat_identity:3014`
- Description: When RMB is ready, **every** status call (desktop polls this every 8s from `useSessionLlm.ts:243` while provider is `rmb`; diagnostics and `/api/auth` model lists also call it) runs `sync_rmb_chat_identity(..., force_provider=True)`. That function **always** `_write_config` — it does not compare-then-skip. It also forces `llm_provider=rmb` and harness percents. A Settings save can lose to the next poll. Disk write + cache invalidate twice per cycle.
- Suggestion: Sync only when stem/provider actually changed. Never write config from a GET. Split a cheap `GET /api/rmb/status?light=1` for the 8s bar poll.

### 2. suggestion — same handler is ~1.6s (measured)

- File: `src/remedy/runtime/rmb/service.py:2468–2706`, `gpu_probe.py:128`
- Description: Live logs: `SLOW GET /api/rmb/status -> 200 (1640–1760ms)` on an 8s cadence. One call does:
  1. `is_running(force=True, require_http=True)` — bypasses 1.5s cache, HTTP `/health` + `/v1/models` (0.9s timeout each)
  2. `is_loading()` — **another** `_health(0.9)`
  3. `_nvidia_ok()` **and** `_gpu_present()` — two uncached `probe_gpus()` → `nvidia-smi` + AMD + Win32 CIM
  4. `discover_ggufs` filesystem walk
  5. `detect_gguf_host_profile` / `plan_autofit` → GGUF header + `probe_hardware()` when the host is down
  6. the config rewrite in Issue 1
- Suggestion: Cache `probe_gpus()` for 30–60s. Do not `force=True` on UI polls. One GPU probe per request. Light status without autofit/discover/sync. Desktop should not full-poll when Settings is closed (bar only needs stem + ready).

### 3. suggestion — Hugging Face pull has no size cap; same basename wins

- File: `src/remedy/runtime/rmb/hf.py:450` (`dest_path`), `:478` (skip if dest > 64 bytes), download loop has no max bytes
- Description: Dest is always `models/{basename}.gguf`. A second repo with the same filename either **overwrites** or, if a file already exists, **skips** as “already downloaded” even when contents differ. No `max_bytes` — a 70B Q8 / malicious huge file fills the disk. Host allowlist + rebuild-URL + HF-only redirects are correct. Token is env-only (good).
- Suggestion: Cap (e.g. 80 GiB) and abort if `Content-Length` exceeds it. Namespace dest as `{owner}--{basename}` when the basename is already present with a different size, or always prefix. Require `expected_size` from the tree listing when present.

### 4. suggestion — Teams JWKS still trusts any `https://` `jwks_uri`

- File: `src/remedy/gateway/channels/jwt_rs256.py:196`
- Description: After fetching Microsoft OpenID docs, any `https://` `jwks_uri` is ingested. Redirects are not host-pinned. Only matters if Teams inbound is enabled and the OpenID doc is poisoned.
- Suggestion: Allowlist `login.botframework.com` / `login.microsoftonline.com` (and documented BF key hosts). Refuse off-host redirects.

### 5. suggestion — skills catalog HTTP still follows redirects blindly

- File: `src/remedy/skills/library/catalog.py:99`
- Description: Initial URL is allowlisted; `aiohttp` follows redirects with no final-URL check (zip install already checks the final URL). SSRF-read of up to 8 MiB; signature still blocks install.
- Suggestion: Re-check `resp.url` with `is_allowed_catalog_url` (CDN exception only for GitHub release hosts).

### 6. suggestion — Rust rail still misses Python’s `metadata` **label** rule

- File: `desktop/src-tauri/src/browser_host.rs:709` vs `src/remedy/core/computer/router.py:38`
- Description: Python blocks any DNS label `metadata` (`metadata.nicob.net`). Rust only exact-matches `metadata` / Google IMDS hosts / `.internal`. Agent `computer_navigate` is filtered in Python first; native-only IPC is the residual.
- Suggestion: `host.split('.').contains(&"metadata")` and add that case next to the existing Rust unit table.

### 7. suggestion — ReAct abort is still between steps only

- File: `src/remedy/core/react_loop/loop.py:737`
- Description: Stop is cooperative at step boundaries. Mid-SSE generation can run until the provider sock_read timeout (long). Desktop persist-on-cancel is fine; tokens/cost still burn.
- Suggestion: Cancel the aiohttp request when the session abort event is set (already used between steps).

### 8. suggestion — `set_turn_tier` / action IR still fall back to the runtime singleton

- File: `src/remedy/core/turn_context.py:537–586`
- Description: `set_turn_force_tool_choice` correctly ignores the singleton. `set_turn_tier`, `set_turn_action_ir`, and `set_turn_shadow_strict` still write `runtime._turn_tier` etc. when ContextVar flags are missing. Cross-tab bleed only if a caller runs outside `TurnReactFlags`.
- Suggestion: Same “ignore runtime” rule as force-tool, or fail closed when flags are unset.

### 9. nit — mypy still excludes the ReAct hot path and HTTP routes

- File: `pyproject.toml:133`
- Description: CI type-check does not cover `react_loop/loop.py` or `interfaces/routes/*`.
- Suggestion: Incrementally add routes (including new `/api/rmb/hf/*`) to `files`.

### 10. nit — HF search third fallback drops `filter=gguf`

- File: `src/remedy/runtime/rmb/hf.py:355`
- Description: After two GGUF-oriented queries, a plain search can list non-GGUF repos. File listing then returns empty — confusing, not unsafe.
- Suggestion: Keep `filter=gguf` on every search page; only widen the search string.

## Suggested fix order

1. Stop writing `config.toml` from `GET /api/rmb/status` (Issue 1) — correctness + a chunk of the 1.6s.
2. Light status + cached GPU probe (Issue 2) — UI snappiness.
3. HF dest namespace + size cap (Issue 3) before people pull 70B files.
4. JWKS host allowlist + catalog final-URL (Issues 4–5) if Teams / catalog refresh are in play.
5. Rust metadata-label parity + mid-SSE abort when touching those files anyway.
